# 07 · 账号权限勾选设计（D11 + D7 取消）

> 依据 2026-10-05 用户两轮拍板：
> - **D11**：「不同帐号权限可勾选模块及数据纬度确定，不只是固定方案」+ 二轮细化「角色模板为预设，允许管理员勾选权限」
> - **D7 = 取消**（二轮修订）：「it业务数值权限取消」→ **IT 恒不可见任何业务数值**
>
> 本文是权限模型的落地细则；`docs/01` §13 是总纲，本文是展开。
> 版本 v1.2（2026-10-05 二轮修订：新增 §2.5 勾选组；D7 改取消）

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| **可勾选** | 模块、维度、密级、字段均可**逐项勾选**，不再被固定模板锁死 |
| **有起点** | 角色模板作为「预设套餐」，一键勾选一组，降低配置成本 |
| **DENY 优先** | 显式禁用永远覆盖启用（fail-closed） |
| **可预览** | 勾选结果**即时预览**该账号将看到什么 |
| **可追溯** | 每次勾选变更落审计（谁、给谁、改了什么、何时） |
| **有边界** | 勾选者自身层级限制其可授予范围（不可越权授予） |

---

## 2. 授权客体（四个维度）

```
┌─ 勾选组 (DataUseGroup) ★二轮新增 ─────────────┐
│  运营数据 / 成本与利润 / 库存与预警 / 投资与回报  │
│  → 决定"这批数据用来干什么"（业务用途顶层分组）   │
│  详见 §5.5                                     │
└──────────────────────────────────────────────┘
┌─ 模块 (Module) ──────────────────────────────┐
│  报表 / P&L / 策略实验室 / 模板中心 / IT 控制台  │
│  → 决定"能进哪些页面"                          │
└──────────────────────────────────────────────┘
┌─ 数据维度 (Dimension) ───────────────────────┐
│  品牌 / 渠道 / 店铺 / 品类 / 产品状态 / 套系    │
│  → 决定"能看到哪些行的数据"（ABAC 行级）        │
└──────────────────────────────────────────────┘
┌─ 字段密级 (Level) ───────────────────────────┐
│  L1 公开 / L2 内部 / L3 敏感 / L4 核心          │
│  → 决定"能看到哪些列"（列级）                   │
└──────────────────────────────────────────────┘
        + 逐字段覆写（个别字段提权/降权）
        + 临时授权（时间盒）
```

> 注：**D7 已取消**，`canViewBusinessValues` 不再是可选开关；对 IT 恒为 false（§6）。

## 3. Entitlement 模型

```ts
// 见 contracts/entitlement.ts
{
  account: "zhangsan",
  baseTemplate: "role.brand_manager",     // 起点（可空）
  groups: ["grp_huadong"],                // 用户分组（D12）
  supervisor: "lisi",                     // 上级（D13）
  dataUseGroups: [                        // 四个勾选组（§5.5）
    { group: "grp.ops",        scopedBy: [{ dim: "channel", values: ["TK-TH"], includeDescendants: true }], maxLevel: "L3" },
    { group: "grp.cost_profit", maxLevel: "L3" },
    { group: "grp.inventory",  maxLevel: "L2" }
  ],
  modules: {
    enabled:  ["module.report", "module.pnl"],
    disabled: ["module.strategy"]          // DENY 优先
  },
  dimensions: [
    { dim: "brand",   values: ["KONVY", "ONI"], includeDescendants: true },
    { dim: "channel", values: ["TK-TH"],        includeDescendants: true },
    { dim: "store",   values: [],               includeDescendants: false } // 空=全部（受密级约束）
  ],
  maxLevel: "L3",
  fieldOverrides: [
    { field: "cost_unit", allow: false }   // 该字段单独禁止
  ],
  canViewBusinessValues: true,             // 非 IT 账号；IT 恒 false（D7）
  tempGrants: [
    { scope: "field:seller_discount", expiresAt: "2026-10-20T00:00:00+07:00", grantedBy: "michael" }
  ]
}
```

## 4. 求值顺序（必须严格按此顺序）

```
1. 展开 baseTemplate  →  得到起点权限集
2. 并入逐项勾选        →  modules.enabled / dimensions / maxLevel / fieldOverrides
3. 并入临时授权        →  tempGrants（仅未过期）
4. 减去 DENY           →  modules.disabled + fieldOverrides(allow=false)
5. 应用授予者层级上限   →  勾选者不能授予超过自己层级的范围
6. 输出 EntitlementView（含 source 溯源）
```

**铁律**：
- **DENY 优先**：第 4 步在任何并入之后执行，确保显式禁止永远生效。
- **未授予即拒绝**：不在任何启用集中的模块/维度/字段，一律不可见（fail-closed）。
- **不可越权授予**：T3 主管不能授予 T1 级范围（第 5 步强制）。

## 5. 勾选树交互（UI 规格）

| 区域 | 内容 |
|---|---|
| 左：模块树 | `模块 → 页面 → 组件`，逐级勾选，支持全选/反选 |
| 中：维度树 | `维度 → 取值`（品牌的渠道、渠道的店铺…），可勾「包含下级」 |
| 右：密级与字段 | 密级上限单选；字段列表逐项勾选覆写 |
| 底：预览 | 「该账号将看到」实时预览（页面 + 行数 + 列数 + 密级） |

**交互要求**
- 任何勾选变更 → **即时预览**（本地求值，无需保存）。
- 保存 → 服务端复验（服务端是唯一权威）→ 落审计。
- 支持「另存为套餐」：把当前勾选保存为自定义模板，供其他账号复用。

## 5.5 勾选组（数据用途组）★ 二轮新增

勾选树的**顶层**不是散装字段，而是按**数据用途**分成的四个「勾选组」。
管理员/申请人先勾「组」，组内再细到维度与字段。这样勾选语义与业务用途一致，避免"勾了字段却不知用来干什么"。

### 四个勾选组

| # | 勾选组 | 组 ID | 包含的数据 | 典型用途 |
|:--:|---|---|---|---|
| ① | **运营数据** | `grp.ops` | 选定**渠道或店铺**后对应的**实际销售数据** + **成本数据**（广告费用、平台费用等的**分项与合计**） | 渠道/店铺日常运营监控、投放效果 |
| ② | **成本与利润** | `grp.cost_profit` | 成本明细、毛利、净利、费用结构 | 经营分析、成本管控 |
| ③ | **库存与库存预警** | `grp.inventory` | 库存数量、在途、周转、**预警阈值与预警项** | 补货决策、断货/滞销预警 |
| ④ | **整体投资与回报** | `grp.roi` | 投资额、回报，**联动库存 + P&L + 时间**三维关系 | 战略投资评估、回报周期 |

### ① 运营数据（`grp.ops`）的子结构

```
grp.ops （运营数据）
  ├─ 维度前置：渠道 / 店铺（选定后限定范围）
  ├─ 实际销售数据
  │    ├─ 销量 / 销售额(GMV) / 订单数 / 客单价 / 退款
  ├─ 成本数据
  │    ├─ 广告费用（Ad Spend）
  │    │    ├─ 渠道级广告费（TikTok / Shopee…）
  │    │    ├─ 分项：曝光/点击/转化费用、达人佣金
  │    │    └─ 合计
  │    ├─ 平台费用（Platform Fee）
  │    │    ├─ 佣金 commission / 支付手续费 / 服务费
  │    │    ├─ 分项明细
  │    │    └─ 合计
  │    └─ 其他成本（物流/仓储/退货处理…）
  ├─ 成本合计（广告 + 平台 + 其他）
  └─ 口径与覆盖率标注（缺失显示「待接入」，不补 0）
```

> **关键**：运营数据组**必须先定渠道或店铺**，否则范围无限大。
> 勾选组时可选择「限定到某渠道/店铺」或「全部（受密级与职权约束）」。

### ② 成本与利润（`grp.cost_profit`）

| 数据 | 说明 |
|---|---|
| 成本明细 | 商品成本 / 物流 / 仓储 / 广告 / 平台费 / 其他 |
| 毛利 | GP = 净收入 − 商品成本 |
| 净利 | Net Profit（口径见 `docs/03`） |
| 费用结构 | 各费用占总收入比例 |
| 口径 | 支持 A 参考口径 / B Finance 口径切换 |

### ③ 库存与库存预警（`grp.inventory`）

| 数据 | 说明 |
|---|---|
| 库存数量 | 在库 / 在途 / 可用 |
| 周转 | 周转天数 / 周转率 |
| **预警阈值** | 各 SKU 的安全库存线、补货点 |
| **预警项** | 断货风险 / 滞销风险 / 超期库龄 |
| 用途 | 补货决策、风险看板 |

> 预警属**衍生结论**，须标注所依据的算法与阈值来源（`docs/03`）。

### ④ 整体投资与回报（`grp.roi`）

**三维关联**：投资 ↔ 库存 ↔ P&L ↔ 时间。

| 数据 | 说明 |
|---|---|
| 投资额 | 采购/备货/投放等资本投入 |
| 回报 | 毛利 / 净利 / 现金流回正 |
| **时间维度** | 回报周期、回本周期、月度/季度趋势 |
| **库存联动** | 库存占用资金、库存周转对回报的影响 |
| **P&L 联动** | 从 P&L 取净利口径，计算 ROI / ROAS |
| 用途 | 战略级投入决策、跨期比较 |

> 本组是**跨模块联动组**：同时依赖 `M-REPORT`（库存）、`M-PNL`、时间序列。
> 缺任一数据源 → 对应指标 `null` + 「待接入」，不部分填充。

### 勾选组的附加语义

| 语义 | 说明 |
|---|---|
| 组可整选 | 勾组 = 勾选组内全部子项（可在组内再取消个别项） |
| 组有依赖 | `grp.roi` 依赖 `grp.cost_profit` + `grp.inventory`；勾 ROI 自动提示需先有前两者 |
| 组有密级 | 每组有默认密级上限，可逐组调整 |
| 组可组合 | 一个账号可勾多个组（如运营 + 库存） |
| 组落审计 | 每次组级勾选变更落审计（记录到组 ID） |

### 与四组对应的契约扩展

```ts
// contracts/entitlement.ts 追加
export type DataUseGroup =
  | "grp.ops"            // 运营数据
  | "grp.cost_profit"    // 成本与利润
  | "grp.inventory"      // 库存与库存预警
  | "grp.roi";           // 整体投资与回报

export interface GroupScopeGrant {
  group: DataUseGroup;
  /** 组内可访问的字段子集；空 = 组内全部 */
  fields?: string[];
  /** 组内的维度限定（如运营数据限定到某渠道/店铺） */
  scopedBy?: DimensionGrant[];
  /** 组内显式禁用项（DENY 优先） */
  denied?: string[];
  maxLevel: "L1" | "L2" | "L3" | "L4";
  /** 组依赖是否已满足（grp.roi 需 cost_profit + inventory） */
  dependenciesMet?: boolean;
}
```

## 6. D7 落地（二轮修订）：IT 业务数值权限 —— **取消**

用户第二轮明确：**「it业务数值权限取消」**。因此本节的"受控可见"作废，改为**恒不可见**：

| 控制 | 措施 |
|---|---|
| 默认 | IT 账号 `canViewBusinessValues = false` |
| 勾选 | **该开关对 IT 恒为 false，且在 UI 上置灰不可点**（不可开启） |
| 业务字段 | IT 对全部业务字段（GMV/成本/售价/毛利/净利…）不可见（L1–L4 全不可见） |
| IT 可见内容 | 仅集成元数据：MCP/API 授权状态、同步水位、错误率、字段映射、账号启用状态 |
| 四组勾选 | IT **不能**勾选 `grp.ops` / `grp.cost_profit` / `grp.inventory` / `grp.roi` 任一业务数据组 |
| 审计 | IT 的控制面操作留痕；无业务访问（因为不访问） |

> **意义**：回到 KODP 的安全红线 —— "系统被攻破"与"经营数据泄露"解耦。
> IT 拥有最大的系统权限，却看不到任何经营数字。

## 7. 与角色模板的关系

```
模板（预设套餐）  ──勾选起点──►  逐项调整（含四个勾选组）  ──►  最终 Entitlement
    │
    └─ 也可完全不用模板，从空集开始勾选
```

| 模板 | 预设内容 |
|---|---|
| `role.admin` | 全部模块 + 四个勾选组 + 全维度 + L4 |
| `role.it` | 集成控制台 + 账号管理 + L1（**无任何业务数据组**，D7） |
| `role.finance` | 报表 + P&L + 策略实验室 + `grp.cost_profit` + `grp.roi` + L4 + 全维度 |
| `role.brand_mgr` | 报表 + P&L + `grp.ops` + `grp.cost_profit` + L3 + 本品牌 |
| `role.channel_ops` | 报表 + P&L + `grp.ops` + `grp.inventory` + L2–L3 + 本渠道 |
| `role.supply_chain` | 报表 + `grp.inventory` + L2 |
| `role.base` | 报表（只读）+ L1 |

> 模板仅是**预设起点**；管理员可在模板基础上自由勾选/取消任何模块、勾选组与维度（D11 二轮细化）。
> 任何勾选组合可「另存为套餐」，纳入套餐列表供复用。

## 8. 审计要求

每条勾选变更落一行：

```
account（被授权者）, actor（操作者）, action（grant/revoke/modify）,
target（模块/勾选组/维度/字段/密级）, before, after, at, reason?
```

审计 append-only，保留 ≥ 180 天，IT 与管理员可查。

## 9. 验收闸门（补充到 `docs/05`）

| 断言 | 说明 |
|---|---|
| G7+1 | 未勾选的模块/维度/字段不进 DOM、不进导出、不进 API |
| G7+2 | DENY 优先：启用与禁用同项时结果为禁用 |
| G7+3 | 勾选者不能授予超过自身层级的范围 |
| G7+4 | **IT 账号 `canViewBusinessValues` 恒 false 且不可勾选**（D7 取消） |
| G7+5 | 每次勾选变更落审计 |
| G7+6 | 预览结果 == 服务端求值结果（一致性） |
| G7+7 | **IT 无法勾选任一业务数据组**（`grp.ops`/`grp.cost_profit`/`grp.inventory`/`grp.roi`） |
| G7+8 | **勾选组依赖校验**：勾 `grp.roi` 而无 `grp.cost_profit`+`grp.inventory` 时给出提示或降级 |
