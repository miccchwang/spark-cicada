## D4 落地口径（混合语言）

用户原话：**「go做业务编排，rust做核心计算与高性能模块」**。据此修订 `docs/01` §4：

| 层 / 模块 | 语言 | 判据 |
|---|---|---|
| 业务编排（`M-QUERY` 编排、`M-ADMIN`、`M-SLOT`、`M-AUTH`、`M-AUDIT`、`M-COLLECT`） | **Go** | 高并发、单二进制部署、生态成熟；**只编排、不重算** |
| 核心计算（`M-ALGO` 法则执行、`M-PRECOMP` 预计算、`M-RULE` 规则求值） | **Rust** | 批量数值运算、无 GC 抖动、类型强、可编译 WASM 复用前端 |
| 高性能模块（滑块实时重算、大结果集聚合、覆盖率校验） | **Rust（+ WASM）** | 毫秒级与 60fps 要求 |
| 前端交互 | **TypeScript + Solid** | — |

**边界纪律**：Go **不写数值公式**（公式一律在 Rust 算法内核）；Rust **不碰 HTTP 编排/鉴权**。
两者通过 gRPC/FFI 边界通信，契约见 `contracts/`。

## D7 的落地与风险控制（IT 可见业务数值）

用户选择 **B（可见）**，与建议的 A（不可见）相反。落地时须补齐以下控制，避免 KODP 的"管数分离"红利丢失：

| 控制项 | 措施 |
|---|---|
| 最小够用 | IT 账号默认仍只给集成元数据权限，**业务数值需显式勾选**（见 D11） |
| 审批 | IT 查看业务数值需走一次显式授权（T1 批准 + 留痕），非默认开启 |
| 留痕 | IT 每次访问业务数值写入审计（谁、何时、看了哪些字段） |
| 字段级 | IT 默认可看 L1/L2；**L3/L4（成本、售价、净利）默认不可见**，需单独授权 |
| 可撤销 | IT 的业务数值权限可被 T1 随时收回 |

> **说明**：此条不影响数据模型，但影响权限矩阵与审计范围，已在 `docs/03`（权限模型）与
> `docs/07`（账号权限勾选）中同步。

## D11（新增）：账号权限可勾选模块与数据维度

用户原话：**「不同帐号权限可勾选模块及数据纬度确定，不只是固定方案」**。

**含义**：不再只有"角色模板 → 固定权限集"这一条路径；每个账号可以被**逐项勾选**：
- 可访问的**模块**（报表 / P&L / 策略实验室 / 模板中心 / IT 控制台 …）
- 可访问的**数据维度**（品牌 / 渠道 / 店铺 / 品类 / 状态 …）
- 可访问的**字段密级**（L1–L4）

**落地**：新增 `Entitlement`（授权项）模型，见 `docs/07-账号权限勾选设计.md`。
角色模板退化为**预设套餐**（一键勾选一组），但**最终权限以逐项勾选结果为准**。
