## D4 落地口径（混合语言）

用户原话：**「go做业务编排，rust做核心计算与高性能模块」**。据此修订 `docs/01` §4：

| 层 / 模块 | 语言 | 判据 |
|---|---|---|
| 业务编排（`M-QUERY` 编排、`M-ADMIN`、`M-SLOT`、`M-AUTH`、`M-AUDIT`、`M-COLLECT`） | **Go** | 高并发、单二进制部署、生态成熟；**只编排、不重算** |
| 核心计算（`M-ALGO` 法则执行、`M-PRECOMP` 预计算、`M-RULE` 规则求值） | **Rust** | 批量数值运算、无 GC 抖动、类型强、可编译 WASM 复用前端 |
| 高性能模块（滑块实时重算、大结果集聚合、覆盖率校验） | **Rust（+ WASM）** | 毫秒级与 60fps 要求 |
| 前端交互 | **TypeScript + Solid** | — |

**边界纪律**：Go **不写数值公式**（公式一律在 Rust 算法内核）；Rust **不碰 HTTP 编排/鉴权**。
两者通过 gRPC/FFI 边界通信，契约见 `contracts/`。

## D7（第二轮修订）：IT 业务数值权限 —— **取消**

用户第二轮原话：**「it业务数值权限取消」**。

**最终口径**：**IT 不获得业务数值权限**，回到「管数分离」原则。

| 项 | 最终落地 |
|---|---|
| IT 可管理 | MCP/API 授权与状态、账号启用、用户分组、权限申请审批（**元数据层**） |
| IT 不可见 | **任何业务数值**（GMV / 成本 / 售价 / 毛利 / 净利…） |
| 字段级 | IT 对业务字段一律不可见（L1–L4 全不可见） |
| 实现 | `Entitlement.canViewBusinessValues` 对 IT 角色**恒为 false**，且**不可被勾选开启** |
| 审计 | IT 的全部控制面操作留痕；不含业务数值访问（因为不访问） |

> **意义**：这一条回到了 KODP 的安全红线 —— "系统被攻破"与"财务数据泄露"解耦。
> IT 拥有最大的系统权限，却看不到任何经营数字。

**最终口径**：

| 项 | 决策 |
|---|---|
| 角色模板 | **预设**（起点），不是权限的唯一来源 |
| 勾选者 | **管理员**可勾选权限（赋予/调整账号的模块、维度、密级） |
| 勾选客体 | 模块 / 数据维度（行级）/ 字段密级（列级）/ 逐字段覆写 |

**落地**：`contracts/entitlement.ts` + `docs/07-账号权限勾选设计.md`；

### B1–B3 · 容灾与备份

**用户原话（三轮补充）**：**「双云主备是每个地域服务器都要有主备两组，新加坡负责东南亚业务，美国负责美区业务」**。

| # | 决策 | 落地 |
|:--:|---|---|
| B1 | **双地域 × 每地域主备**：新加坡（东南亚）/ 美国（美区）各一套「阿里云主 + AWS 备」；**地域内异步同步** | `docs/04` §6.1–6.2 |
| B2 | **分地域保留 180 天**数据回滚能力（互不干扰，仅本地域） | `docs/04` §6.3 |
| B3 | **云数据可本地备份 + 下载；每月 1 号自动备份上一个月；每月限 1 次下载（分地域计数）** | `docs/04` §6.4 |

**拓扑要点**
```
新加坡地域：阿里云 ap-southeast-1 (主)  ──同地域异步──►  AWS ap-southeast-1 (备)
  承接：东南亚渠道/店铺（TK-TH / Shopee-TH …）

美国地域：  阿里云 us-east-1 (主)        ──同地域异步──►  AWS us-east-1 (备)
  承接：美区渠道/店铺
```
- **地域间业务分区，互不互为实时备**；仅做汇总视图 / 灾备归档（避免跨洋延迟）。
- **禁止跨地域写同一行数据**；跨地域只做"读汇总"。
- 同地域内网延迟低 ⇒ 备库 RPO 可达**秒级**（优于跨洋方案）。
- 异步 ⇒ RPO > 0；下载 URL 用一次性签名（符合 `docs/09` 无凭据铁律）。
