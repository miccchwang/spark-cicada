# 09 · 凭据防泄漏章程

> 落地用户第二轮要求：**「避免参考项目的 URL 直接显示用户名称与密码的问题」**。
> 直接针对 KODP 实测缺陷设计。是 `docs/01` §18 的独立展开。
> 版本 v1.0（2026-10-05）

---

## 1. 问题溯源（KODP 实测缺陷）

对参考项目 `miccchwang/Trading-Strategy-and-Management-` 的排查发现**三处**凭据暴露风险：

| # | 位置 | 现象 | 危害等级 |
|:--:|---|---|:--:|
| 1 | `frontend/public/config.json` | 提交进 Git，且被静态服务公开可读，内含 70 字符 `oauth_client_secret` | **P0 严重** |
| 2 | `git stash@{0}` | 残留明文 secret | **P0 严重** |
| 3 | 页面 URL 传参 | 存在把账号/参数直接拼进 URL 的形态 | **P1 高危** |

> `frontend/public/` 是**构建后原样拷贝到公开静态目录**的路径。
> 在这里放 secret，等价于把密钥挂到公网。

---

## 2. 四条铁律（本项目强制执行）

| # | 铁律 | 落地方式 | 违反后果 |
|:--:|---|---|---|
| **R1** | **URL 不含凭据** | 站点禁止 `scheme://user:pass@host`；前端路由参数白名单；身份只走 Header/Cookie/ticket | 阻断合并 |
| **R2** | **前端产物零密钥** | `public/`、`dist/` 只允许公开配置（API 基址、功能开关）；secret 一律留存服务端，由后端代理 | 阻断发布 |
| **R3** | **密钥不入 Git** | `.gitignore` 强制排除 `.env*` / `*.pem` / `*_secret*` / `credentials*`；密钥经环境变量或 Vault/KMS 注入 | 阻断合并 |
| **R4** | **密钥不入镜像** | Dockerfile 禁 `COPY .env`；用 `--mount=type=secret` 或运行时注入；镜像层扫描 | 阻断推送 |

## 3. URL 脱敏设计（核心）

### 3.1 禁止形态 → 替代形态

| 场景 | ❌ 禁止（KODP 问题形态） | ✅ 本项目采用 |
|---|---|---|
| 店铺详情跳转 | `/store?user=xxx&password=yyy` | `/store/:id`；身份从 HttpOnly Cookie 读 |
| 报表分享链接 | `/report?token=<长寿命JWT>` | 一次性短时 ticket，用后即焚 |
| 外部平台 OAuth 回跳 | 回跳 URL 带 `client_secret` | 回跳只带 `code`，secret 在服务端交换 |
| IT 控制台看平台凭证 | 页面直接回显明文 secret | 只显示掩码 `sk-****abcd` + 「轮换」按钮 |
| 站内单点跳转 | URL 带账号标识 | 短时 ticket（60s）或直接服务端 session |
| 打印/导出链接 | URL 含身份参数 | 签名 URL（HMAC，短时）+ 权限校验 |

### 3.2 统一认证载体

```
浏览器 ──(HttpOnly + Secure + SameSite Cookie)──► Go 编排层
                                                    │
                                                    ├─ 校验 session
                                                    ├─ 解析 Entitlement
                                                    └─ 注入内部身份头（仅内网）
```

- **前端从不持有长期凭据**；Token 只存于 HttpOnly Cookie，JS 不可读。
- 跨服务调用用**内部 mTLS / 服务令牌**，不经 URL。
- 一次性 ticket 用 Redis 存储，TTL 60s，使用后立即删除。

### 3.3 中间件拦截规则

| 规则 | 行为 |
|---|---|
| 请求 URL 匹配 `scheme://[^/]*:[^/]*@` | 直接 400 拒绝 |
| 前端路由 query 含敏感键名（`password`/`secret`/`token`/`api_key`） | 拦截并记安全日志 |
| 响应体含明文 secret 形态（生产环境） | 拦截并告警 |
| 日志写入前 | 正则脱敏 `(?i)(secret\|token\|password\|api[_-]?key)\s*[:=]\s*\S+` |

## 4. 密钥存储与流转

```
生产：  Vault / 云 KMS（阿里云 KMS / AWS Secrets Manager）→ 运行时注入环境变量
开发：  .env.local（git-ignored），独立低权凭据，不复用生产
构建：  Docker BuildKit --mount=type=secret，不落层
CI：    仅从 CI Secret Store 注入，且不打印
```

| 项 | 规则 |
|---|---|
| 存储位置 | 生产密钥存 Vault/KMS；本地 `.env.local` 且 git-ignored |
| 权限 | 每个平台凭据只授予必要 scope；IT 不持业务数值访问权（D7） |
| 日志 | 日志系统对 secret 字段自动脱敏（正则 + 白名单） |
| 轮换 | 一键轮换 + 双活窗口（新旧并存 ≤ 24h）；轮换落审计 |
| 最小化 | 任何 secret 只在**需要它的服务进程内存**中存在 |

## 5. CI 闸门 G11（对应 `docs/05` §G11）

| 子闸门 | 检查 | 工具/方式 |
|---|---|---|
| G11a 提交扫描 | 高熵字符串、`client_secret` / `api_key` / `access_token` / 私钥头、`user:pass@` URL | `gitleaks` / `trufflehog` + 自研正则 |
| G11b 前端产物扫描 | `dist/`、`public/` 内 secret 形态 | 构建后扫描脚本 |
| G11c 镜像层扫描 | 镜像层内 `.env` / secret 文件 | `docker history` + 层解包扫描 |
| G11d 日志脱敏 | 注入含 secret 日志，断言输出已脱敏 | 单元测试 |
| G11e 历史全量扫描 | 季度任务，全 Git 历史 | 定时任务 + 报告 |

> 任一失败 → **阻断合并/发布/推送**。
> 一旦发现历史泄漏：**轮换 → 重写历史（`git filter-repo`）→ 通知** 三段处置。

## 6. 自查清单（提交前必查）

- [ ] URL 里没有任何账号、密码、token、密钥
- [ ] `public/` 与 `dist/` 里没有任何 secret
- [ ] `.env` 系列文件未被 `git add`
- [ ] `git stash list` 里没有残留明文密钥
- [ ] Dockerfile 没有 `COPY .env`
- [ ] 日志里输出的是掩码而非明文
- [ ] IT 控制台页面显示的是掩码而非明文
- [ ] 新增第三方凭据已登记到 Vault 且有轮换计划

## 7. 与 KODP 的关系

本项目**不复制** KODP 的凭据处理方式，只**吸取教训**：

| KODP 做法 | 本项目做法 |
|---|---|
| secret 放前端 `public/config.json` | ❌ 禁止；secret 只在服务端 |
| 明文进 Git（含 stash） | ❌ 禁止；CI 扫描兜底 |
| URL 可带身份参数 | ❌ 禁止；走 Cookie/ticket |
| 无密钥轮换机制 | ✅ Vault/KMS + 一键轮换 + 双活窗口 |
