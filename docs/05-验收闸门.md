# 05 · 验收闸门（CI Gates）

> 承袭 KODP 的「闸门」思想：把架构约束变成**可自动失败的断言**，防止设计随时间腐化。
> 版本 v1.2（2026-10-05 二轮修订：新增 G12 备份与容灾闸门；G7 补充权限细则）

---

## 1. 为什么需要闸门

KODP 的经验：**设计写在文档里会漂移，写在闸门里才不会**。
本项目的架构约束（三段式解耦、默认收起、缺失不补 0 等）全部固化为断言。

---

## 2. 闸门清单

### G1 · 分层依赖闸门

| 断言 | 说明 |
|---|---|
| `M-FILTER` 不含网络调用 | 静态分析：无 `fetch` / `axios` / `http` 引用 |
| `M-RENDER` 不读 `QueryState` | 静态分析：渲染模块无 `QueryState` 导入 |
| `M-QUERY` 不含业务公式 | 静态分析：无 `gp` / `cogs` / `gmp` 字面公式 |
| 无反向依赖 | L5 不直接依赖 L2 及以下 |

### G2 · 默认收起闸门

| 断言 | 说明 |
|---|---|
| 所有可折叠表格初始 `open=false` | 渲染快照断言（L0 总览除外） |
| `DEFAULT_EXPANDED` 契约值一致 | 单元测试 |

### G3 · 缺失值闸门

| 断言 | 说明 |
|---|---|
| 任何非空值有 `AlgoTrace` 且 `skipped=false` | 契约校验 |
| `skipped=true` 的字段值必为 `null` | 契约校验 |
| 页面不出现用于占位的 `0` | 渲染断言（真实计算为 0 除外，需白名单） |
| 缺失显示文案为 `待接入` / `—` | 渲染断言 |

### G4 · 算法/数据槽分离闸门

| 断言 | 说明 |
|---|---|
| 算法 YAML 中无数据源字段 | schema 校验：`formula` 不含 `source` / `table` |
| 每个 `depends_on_slots` 已注册 | 引用完整性 |
| 每个槽有 `coverage_gate` | schema 校验 |

### G5 · 覆盖率门控闸门

| 断言 | 说明 |
|---|---|
| 覆盖率 < 门限 → 依赖算法 `skip` | 注入低覆盖数据，断言跳过 |
| 不补 0、不摊分 | 断言输出为 `null` |

### G6 · 预计算一致性闸门

| 断言 | 说明 |
|---|---|
| 桶 `algo_version` == 注册表版本 | 启动检查 |
| 桶数据与源数据对平 | 抽样重算对比 |
| 算法升级后仅重算受影响桶 | 变更后断言 |

### G7 · 权限闸门

| 断言 | 说明 |
|---|---|
| 无权字段不进 DOM | 渲染断言 |
| 无权字段不进导出 | 导出断言 |
| 无权字段不进 API 响应 | 接口断言 |
| IT 账号无法读业务数值 | 端到端断言 |
| **IT 的「业务数值」勾选项置灰不可点** | UI 断言（D7=取消） |
| **代授不溢出**：下级权限 ⊆ 上级权限 | 注入越权代授，断言被拒（D13） |
| **分组 DENY 优先** | 分组授权与个人勾选冲突时取 DENY（D12） |
| **申请未批不通** | 未走完审批的 Entitlement 不生效（D14） |
| **+1 审批 / +2 抄送** | 提交后仅 +1 进审批队列；+2 或 +1 的直属上级进抄送列表 |
| **跨部门不可自助申请** | 跨部门数据项在自助申请页置灰；提交状态置 `BLOCKED_CROSS_DEPT` |
| **跨部门须 T1 批准** | 注入"非 T1 批准跨部门授予"，断言被拒 |
| **IT 不可勾选任一业务数据组** | 断言 `grp.ops`/`grp.cost_profit`/`grp.inventory`/`grp.roi` 对 IT 均不可选 |
| **勾选组依赖校验** | 勾 `grp.roi` 而缺 `grp.cost_profit`+`grp.inventory` 时提示/降级 |
| **会签触发** | 注入 L4 / 跨部门 / 有效期>90天 / 含 `grp.roi`·`grp.cost_profit` / 批量≥10 的申请，断言状态置 `COSIGN_PENDING` |
| **会签否决生效** | 会签人否决后，申请必须为 `REJECTED`，权限不生效 |
| **知会不阻断** | 默认模式下抄送人未阅知，不阻断 +1 审批通过 |

### G8 · 性能闸门

| 断言 | 阀值 |
|---|---|
| 首屏 TTI | < 1000 ms |
| 筛选 P95（命中预计算） | < 100 ms |
| 筛选 P95（未命中） | < 500 ms |
| 首屏产物 gzip | < 200 KB |

### G9 · 插槽闸门

| 断言 | 说明 |
|---|---|
| 新模块零改主机即可挂载 | 集成测试（挂个示例模块） |
| 能力不满足时降级不崩 | 注入缺失槽，断言降级渲染 |
| 模块可独立停用 | 停用后其他模块正常 |

### G10 · 策略与审计闸门

| 断言 | 说明 |
|---|---|
| 每个策略变更落一行历史 | 断言表行数增加 |
| 策略可回滚 | 回滚后参数等于上一版本 |
| 审计 append-only | 尝试修改/删除审计行必须失败 |

### G11 · 密钥与凭据泄漏闸门（二轮修订新增）

> 直接针对 KODP 实测缺陷：`frontend/public/config.json` 公开托管 `oauth_client_secret`；`git stash` 残留明文。
> 详见 `docs/01` §18「凭据防泄漏章程」。

| 断言 | 说明 |
|---|---|
| **仓库无高熵密钥** | 对每个提交跑 `gitleaks` / `trufflehog`，命中即阻断 |
| **URL 无凭据形态** | 正则拦截 `scheme://user:pass@host`；前端路由参数白名单校验 |
| **前端产物零 secret** | 扫描 `dist/`、`public/`，命中 `client_secret`/`api_key`/私钥头即阻断发布 |
| **镜像层零 .env** | 构建后扫描镜像层内 `.env` / secret 文件 |
| **日志不落 secret** | 注入含 secret 的日志，断言输出已脱敏 |
| **IT 页面不回显平台明文凭证** | UI + 接口断言：只返回掩码 |
| **历史全量扫描可跑** | 季度任务：全 Git 历史扫描脚本可执行并产出报告 |

### G12 · 备份与容灾闸门（二轮修订新增）

> 对应 `docs/04` §6（双地域 × 每地域主备 / 地域内异步同步 / 分地域 180 天回滚 / 分地域月度备份下载 / 半自动切换脑裂防护）。

| 断言 | 说明 |
|---|---|
| **地域内同步延迟可观测** | 注入延迟，断言延迟指标上报且超阈值告警（**每地域分别**校验） |
| **备库只读** | 对备库写入必须失败 |
| **禁止跨地域写同一行** | 断言跨地域写同一行数据被拒（仅允许读汇总） |
| **分地域 180 天回滚点可达** | 抽样验证本地域 180 天内任一日的回滚点可恢复，且**不影响另一地域** |
| **回滚不动审计** | 执行回滚后断言审计表行数不减、内容不变 |
| **回滚前先快照** | 断言回滚操作前已生成当前状态快照 |
| **切换必先 fencing** | 断言提升备库前旧主写入通道被隔离（禁止跳过） |
| **月度下载配额生效（分地域）** | 同一地域同月第二次下载必须被拒，并返回下次可下载时间 |
| **每月 1 号自动备份上月（分地域）** | 定时任务断言：1 号**每地域分别**生成上月归档 |
| **下载 URL 无凭据** | 签名 URL 断言：短时效、不含账号密码/token（与 G11 呼应） |
| **归档不含密钥** | 扫描归档内容，命中 secret 即阻断 |
| **恢复演练可执行** | 季度演练脚本可执行并产出 RTO/RPO 报告 |

---

## 3. 闸门执行

```bash
make gate          # 全部闸门
make gate-fast     # 静态闸门（G1/G4/G5）
make gate-render   # 渲染类（G2/G3/G7）
make gate-perf     # 性能（G8）
make gate-secret   # 密钥扫描（G11）
make gate-dr       # 备份与容灾（G12）
```

任一闸门失败 → **阻断合并**（承袭 KODP 的「两个浏览器闸门转阻断」经验）。

---

## 4. 新增闸门的纪律

新增架构约束时：
1. 先在 `docs/01` 写明约束；
2. 再在本文档加一条闸门；
3. 最后实现断言。

**顺序不可颠倒** —— 先有约束定义，才有断言。
