## 1. 环境与部署

### 1.1 组件清单

| 组件 | 规格（云主机参考） | 语言 | 说明 |
|---|---|---|---|
| `app` | 2C4G | **Go** | 业务编排（M-QUERY/M-SLOT/M-ADMIN/M-AUTH/M-AUDIT/M-COLLECT） |
| `compute` | 4C8G | **Rust** | 核心计算内核（M-ALGO/M-PRECOMP/M-RULE） |
| `db` | 4C8G + SSD | PostgreSQL 15+ | 事实表 + 维表 + 预计算桶 |
| `cache` | 2C4G | Redis | 查询缓存 / QueryState 去重 / 失效通知 |
| `web` | 静态 | Nginx / CDN | Solid 前端产物 |

> 最小可行（POC）：1 台 4C8G 跑全部，Compose 起。

### 1.1.1 双地域 × 每地域主备（D1：阿里云 + AWS）

**两个地域，每个地域内部各有一套主备**；地域按业务分区，不互为跨洋备。

| 地域 | 业务 | 主（Primary） | 备（Standby，同地域） | 组件 |
|---|---|---|---|---|
| **新加坡** | 东南亚 | 阿里云 · ap-southeast-1 | AWS · ap-southeast-1 | 主：app+compute+db+cache+web；备：db 热备 + app/compute 冷备 |
| **美国** | 美区 | 阿里云 · us-east-1 | AWS · us-east-1 | 同上 |

- 每个地域**独立**一套 Compose；地域内主备经**同地域内网加密通道**异步同步。
- 用户/数据按**业务地域**就近接入（东南亚→新加坡；美区→美国）。
- 地域间仅做**汇总视图 / 灾备归档**，不做实时主备（避免跨洋延迟）。
- 明细见 §6.1。

### 1.2 部署形态（D5 = Docker Compose）

**网络基线（D9 = 纯内网 + VPN）**：
- 生产**不暴露公网**；全部访问经 VPN。
- 安全组只放行 VPN 网段与内网互访。
- 出站仅开钉钉 Stream（长连接）与必要的平台 API。
- 主备同步（**地域内**）走**同地域内网加密通道**，不走公网明文。

```yaml
# deploy/docker-compose.yml（骨架）
services:
  db:
    image: postgres:15
    environment: [POSTGRES_DB=spark, POSTGRES_PASSWORD=***]
    volumes: [pgdata:/var/lib/postgresql/data]
  cache:
    image: redis:7
  app:                      # Go 业务编排
    build: ./backend
    depends_on: [db, cache]
  compute:                  # Rust 计算内核
    build: ./compute
  web:
    image: nginx:alpine
    volumes: [./web/dist:/usr/share/nginx/html:ro]
```

### 1.3 环境变量

| 变量 | 说明 |
|---|---|
| `SPARK_DB_DSN` | 数据库连接串（生产强制，缺失拒启） |
| `SPARK_REDIS_URL` | 缓存 |
| `SPARK_SECRET_KEK` | 密钥加密主密钥（**不进 Git**） |
| `SPARK_LOG_LEVEL` | 日志级别 |

**纪律**：生产缺 DSN 直接拒启（fail-fast），不静默降级到本地 SQLite。

## 3. 预计算运维

### 3.1 刷新任务

| 桶 | 频率 | 命令 | 预计耗时 |
|---|---|---|---|
| `pnl_daily` | 每日 T+1 | `spark-pc refresh pnl_daily` | < 30s |
| `pnl_month` | 每日 + 月终结转 | `spark-pc refresh pnl_month` | < 2min |
| `stock_snapshot` | 每日 | `spark-pc refresh stock_snapshot` | < 20s |
| `kpi_summary` | 每日 | `spark-pc refresh kpi_summary` | < 10s |

### 3.2 失效与重算

| 事件 | 动作 |
|---|---|
| 数据落地 | 标记相关桶 `stale` |
| 算法升版本 | `spark-pc rebucket --algo <id>` 只重算该算法产出的桶 |
| 规则变更 | `spark-pc rebucket --rule <id>` 重算依赖规则的桶 |
| 全量重建 | `spark-pc rebuild-all`（慎用，串行执行） |

### 3.3 健康检查

```bash
spark-pc status          # 各桶：行数 / 最后刷新 / algo_version / stale 标记
spark-pc verify          # 闸门：桶与源数据对平
```

## 4. 集成控制面运维

### 4.1 MCP / API 状态巡检

| 检查 | 频率 | 动作 |
|---|---|---|
| MCP 服务器探活 | 每小时 | 失败 → 状态置 `DEGRADED` + 告警 |
| API token 有效期 | 每日 | < 7 天 → 提醒刷新 |
| 配额消耗 | 每小时 | > 80% → 告警 |
| 账号启用状态 | 每次调用前 | `DISABLED` 直接拒绝 |

### 4.2 常见故障（承袭 KODP 实战经验）

| 症状 | 根因 | 处置 |
|---|---|---|
| 「已授权但发送失败」 | 授权状态 ≠ 可用性 | 查探活日志；确认机器人/账号在目标群/店 |
| 「BC 有但无 advertiser」 | 账号层级缺失 | 在平台侧补建 advertiser 账号 |
| 429 限流后长时间不恢复 | 无断点续传，整月重放 | 检查游标是否落库（§6.3） |
| Token 过期未自动刷新 | 刷新任务未跑 | 检查 OAuth refresh 任务 |
| 数值突然变化 | 口径/费率变更 | 查 `rule_version` 与策略历史 |

## 6. 备份、容灾与恢复（三轮修订 · **每地域一套主备**）

### 6.1 拓扑：双地域 × 每地域主备（D1 细化落地）

用户明确：**「双云主备是每个地域服务器都要有主备两组，新加坡负责东南亚业务，美国负责美区业务」**。

⇒ 架构是 **两个地域（Region）**，**每个地域内部各有一套主备**；地域之间是**业务分区**，不是跨洋主备。

```
┌─────────────────── 地域 A：新加坡（东南亚业务）───────────────────┐
│                                                                  │
│   ┌──── 主（Primary）────┐  同地域异步同步  ┌── 备（Standby）──┐ │
│   │ 阿里云 · ap-southeast-1│ ──────────────► │ AWS · ap-southeast-1│ │
│   │ app + compute + db     │  WAL 流式      │ db 热备(只读)       │ │
│   │ ← 东南亚全部读写        │  加密通道      │ + app/compute 冷备  │ │
│   └────────────────────────┘                └────────────────────┘ │
│              承接：TK-TH / Shopee-TH / 东南亚渠道与店铺              │
└──────────────────────────────────────────────────────────────────┘
                                │
                    （跨地域仅做「汇总视图 / 灾备归档」，
                       不做实时主备，避免跨洋延迟）
                                │
┌─────────────────── 地域 B：美国（美区业务）──────────────────────┐
│                                                                  │
│   ┌──── 主（Primary）────┐  同地域异步同步  ┌── 备（Standby）──┐ │
│   │ 阿里云 · us-east-1     │ ──────────────► │ AWS · us-east-1    │ │
│   │ app + compute + db     │  WAL 流式      │ db 热备(只读)       │ │
│   │ ← 美区全部读写          │  加密通道      │ + app/compute 冷备  │ │
│   └────────────────────────┘                └────────────────────┘ │
│              承接：美区渠道与店铺（TikTok US / 美区站点）            │
└──────────────────────────────────────────────────────────────────┘
```

| 项 | 决策 |
|---|---|
| 地域划分 | **新加坡** → 东南亚业务；**美国** → 美区业务 |
| 每地域结构 | **主（Primary）+ 备（Standby）两组**，各自独立一套 Compose |
| 主 | 阿里云（对应地域区域），承担该地域全部读写 |
| 备 | AWS（**同地域**区域），热备只读副本 + 计算冷备；主故障时提升 |
| 地域间 | **业务分区、互不互为备**；仅做汇总视图与灾备归档（避免跨洋实时复制的高延迟） |
| 路由 | 用户/数据按**业务地域**就近接入；东南亚走新加坡，美区走美国 |
| 切换 | 各地域**独立**切换：本地域主故障 → 提升本地域备（需 T1 确认） |

**为什么不做跨洋主备**：跨洋 RTT 高（>200ms），同步复制会严重拖慢写入；
且两地域**业务本就独立**（不同市场的渠道/店铺/费率），无需互为实时副本。

### 6.1.1 数据归属与汇总

| 数据 | 归属 | 说明 |
|---|---|---|
| 东南亚渠道/店铺数据 | 新加坡地域 | 本地读写 |
| 美区渠道/店铺数据 | 美国地域 | 本地读写 |
| 品牌/产品主数据 | 主地域（新加坡）+ 同步到美国 | 全局共享维表，异步同步 |
| **全局汇总报表** | 各主地域**只读汇总** | 跨地域聚合在应用层完成，不跨地域写同一张表 |
| 审计/权限/密钥元数据 | 各地域**本地存储** + 定期归档 | 走 F11（已拍板 **C 分级**）**同步复制**链路，RPO≈0 |

> **纪律**：**禁止跨地域写同一行数据**（防冲突）；跨地域只做"读汇总"。

### 6.2 地域内异步同步

| 项 | 做法 |
|---|---|
| 范围 | **同地域内**（主 → 备），不跨洋 |
| 方式 | **异步**（不阻塞主库写入） |
| 机制 | PostgreSQL **WAL 流式复制**（`pg_receivewal` / logical replication）+ 定期基线快照 |
| 通道 | **同地域内网加密通道**（延迟低、稳定） |
| 延迟 | 正常 < 1 秒（同地域）；抖动时排队补偿，不丢数据 |
| 冲突 | 备为**只读**，单向主→备，无写冲突 |
| 监控 | 同步延迟指标；超阈值（如 > 30s）告警 |
| 切换后 | 原主恢复后降级为备，反向同步（需人工确认，避免脑裂） |

> **注意**：异步同步 ⇒ **RPO > 0**（可能丢最后几秒）。同地域延迟低，实际丢失窗口很小；
> **审计/权限/密钥等"不可丢"元数据**按 `docs/11` F11（已拍板 **C 分级**）走**同步复制**，
> 即"业务库异步 + 元数据库同步"的**分级口径**，RPO≈0。

### 6.3 备份回滚（180 天 · 分地域）

| 项 | 决策 |
|---|---|
| 回滚窗口 | **各地域的备云各保留 180 天**可回滚点（互不干扰） |
| 回滚粒度 | 支持按**天**回滚（180 个回滚点）；月/周快照额外保留 |
| 范围 | **仅本地域数据**（新加坡地域回滚不影响美区） |
| 触发方式 | 仅 **T1 管理员**可发起；需二次确认 + 记录理由 |
| 回滚对象 | 数据库（事实表 + 桶 + 配置）；不含审计表（审计**永不回滚**） |
| 隔离 | 回滚前先**快照当前状态**，便于反悔（回滚的回滚） |
| 演练 | 每季度演练一次，验证 180 天内任一点可恢复 |

```
可回滚点 = { 每日全量快照 × 180 天 } ∪ { 每周快照 × 52 周 }
回滚流程：选择回滚点 → 预览差异 → T1 二次确认 → 快照当前 → 执行回滚 → 校验 → 留痕
```

### 6.4 本地备份下载（月度配额）

用户要求：**云数据可本地备份，提供下载功能，但限制每月 1 次（1 号自动备份上一个月），有次数限制**。

| 项 | 决策 |
|---|---|
| 范围 | **分地域**：新加坡地域备东南亚上月数据；美国地域备美区上月数据（各自独立归档） |
| 自动备份 | **每月 1 号**自动备份**上一个月**的数据，生成可下载归档 |
| 下载配额 | **每月 1 次**（自然月内仅可下载一次，**按地域分别计数**） |
| 配额重置 | 每月 1 日 00:00 重置 |
| 归档内容 | 上月数据导出（事实表 + 快照 + 必要维表），格式 Parquet 主 + CSV 辅 + 校验和 |
| 加密 | 归档加密（受 KEK 保护），下载需 T1 授权 |
| 下载方式 | 一次性签名 URL（短时效，**不在 URL 中携带凭据**，符合 `docs/09`） |
| 次数限制 | 后端计数；超额直接拒绝并提示下次可下载时间 |
| 审计 | 每次下载记录：谁、何时、哪个月、**哪个地域**、文件校验和 |
| 手动补备 | 特殊情况下 T1 可手动触发一次"补备"，但不增加下月配额 |

```ts
// 备份下载配额模型
export interface BackupDownloadQuota {
  account: string;
  /** 自然月（YYYY-MM） */
  period: string;
  /** 地域（配额按地域分别计数） */
  region?: Region;
  /** 本月已用次数 */
  used: number;
  /** 本月上限（默认 1） */
  limit: number;
  /** 下一次可下载时间 */
  nextAvailableAt: string;
  /** 可下载的归档列表（1 号自动生成的上月归档） */
  archives: {
    id: string;
    /** 所属地域 */
    region: Region;
    /** 数据月份，如 2026-09 */
    dataMonth: string;
    generatedAt: string;
    sizeBytes: number;
    sha256: string;
    /** 一次性签名 URL（短时效，不含凭据） */
    signedUrl?: string;
  }[];
}
```

> **纪律**：下载 URL 使用**一次性签名 + 短时效**，符合 `docs/09` 的「URL 不含账号密码」铁律；
> 归档文件**不得包含**任何密钥或明文凭据。

### 6.5 备份矩阵与 RPO/RTO

> 每个地域（新加坡 / 美国）**各自**适用下表；地域之间不互相备份。

| 对象 | 频率 | 保留 | 方式 | RPO | RTO |
|---|---|---|---|---|---|
| PostgreSQL（**本地域主**） | 每日全量 + WAL 归档 | 30 天 | `pg_dump` + WAL | < 5min | < 4h |
| PostgreSQL（**本地域备**） | **同地域**异步同步 | **180 天回滚点** | WAL 流式 + 快照 | 秒级 | < 1h（提升备） |
| 原始层归档 | 每日 | 90 天 | JSONL + 对象存储 | 1 天 | < 4h |
| 配置/规则/算法 | 随 Git | 永久 | 版本控制 | — | 分钟 |
| 审计日志 | 实时 | ≥ 180 天 | append-only 表 | 0 | — |
| **本地备份下载** | **每月 1 号（上月 · 分地域）** | 归档永久（用户侧） | 加密归档 + 签名下载 | 1 月 | 小时 |

**恢复演练**：每季度一次，**每地域分别**验证 RTO < 4h、主库 RPO < 5min、备 RPO 秒级、180 天回滚点可达。

> **口径说明**：同地域内网延迟低，备库 RPO 可达**秒级**（优于跨洋方案）；
> **审计/权限/密钥元数据**需 RPO≈0 ⇒ 按 `docs/11` F11（已拍板 **C 分级**）走**同步复制**链路，
> 业务库仍保持**地域内异步**。详见 §6.6。

### 6.6 主备切换与脑裂防护（F13 = B 半自动）

> 用户拍板 **B 半自动**：**自动探测 + 告警**，**T1 一键切换**（不自动切、不自动切回）。
> 适用范围：**每个地域各自**（新加坡 / 美国互不接管）。

**切换流程（地域内）**

```
① 探测：主库健康探针失败 N 次 / 复制延迟超阈 / 地域探针异常
        ↓
② 告警：钉钉 + 邮件双通道，标记「建议切换」，人工确认前数据只读降级提示
        ↓
③ 决策：T1 复核后点击「一键切换」→ 提升本地域备库为主
        ↓
④ 收尾：旧主降级为备、重建复制、写审计、通知业务方
```

**脑裂防护护栏（强制）**

| 护栏 | 规则 |
|---|---|
| **禁止双写** | 同一行数据**任何时刻只有一主**；切换期间对受影响业务**只读降级** |
| **禁止跨地域写** | 跨地域仅允许「读汇总」，绝不写同一行（见 §6.1.1） |
| **Fencing（围栏）** | 提升备库前，**先切断旧主**的写入通道（撤销写角色 / 置 read-only / 断开连接） |
| **见证者仲裁** | 每地域引入独立仲裁者（轻量 consensus），避免「双主都以为自己主」 |
| **版本对账** | 切换后按 LSN / 提交序号对账，冲突行**不自动合并**，转人工判定 + 审计 |
| **T1 兜底** | 自动化失效时，T1 手动执行同一套流程；**一切切换留痕** |

> **纪律**：切换是**高风险操作**，全程审计（谁/何时/原因/前后状态）；任何自动化动作**不得跳过 fencing**。
> 详见 `docs/11` F13。

## 7. 采集链路运维（承袭 KODP 三层解耦）

```
采集层 ──► 原始层 ──► 投影层
（每页COMMIT）（只追加）（写业务表）
```

**护栏**

| 护栏 | 作用 |
|---|---|
| 请求节奏控制 | 控制单位时间调用数 |
| 429 乘性退避 | 降低撞限流概率 |
| 月度请求预算 | **注意**：触顶即放弃该月（KODP 的 fail-open 问题），本项目改为**告警 + 保留部分数据** |
| 分页重复硬失败 | 保证不重复计数 |
| 已覆盖月跳过 | 历史月不重放 |

**本项目改进**：预算触顶不再"放弃整月"，而是**落库已取得的部分 + 告警**，下轮续传。
