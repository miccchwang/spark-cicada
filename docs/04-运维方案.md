## 1. 环境与部署

### 1.1 组件清单

| 组件 | 规格（云主机参考） | 语言 | 说明 |
|---|---|---|---|
| `app` | 2C4G | **Go** | 业务编排（M-QUERY/M-SLOT/M-ADMIN/M-AUTH/M-AUDIT/M-COLLECT） |
| `compute` | 4C8G | **Rust** | 核心计算内核（M-ALGO/M-PRECOMP/M-RULE） |
| `db` | 4C8G + SSD | PostgreSQL 15+ | 事实表 + 维表 + 预计算桶 |
| `cache` | 2C4G | Redis | 查询缓存 / QueryState 去重 / 失效通知 |
| `web` | 静态 | Nginx / CDN | Solid 前端产物 |

> 最小可行（POC）：1 台 4C8G 跑全部，Compose 起。

### 1.1.1 双云部署（D1：阿里云 + AWS）

| 站点 | 云 | 区域 | 角色 | 组件 |
|---|---|---|---|---|
| 主 | 阿里云 | 新加坡 ap-southeast-1 | **Primary** | app + compute + db + cache + web（全量） |
| 备 | AWS | 美国 us-east-1 | **Standby** | db 热备（只读）+ app/compute 冷备 |

- 双云各自一套 Compose；跨云经**加密隧道**同步（§6.2）。
- 备站点平时**不承接流量**，仅同步与待命；主故障时提升（§6.1）。

### 1.2 部署形态（D5 = Docker Compose）

**网络基线（D9 = 纯内网 + VPN）**：
- 生产**不暴露公网**；全部访问经 VPN。
- 安全组只放行 VPN 网段与内网互访。
- 出站仅开钉钉 Stream（长连接）与必要的平台 API。
- 跨云同步走**专用加密隧道**，不走公网明文。

```yaml
# deploy/docker-compose.yml（骨架）
services:
  db:
    image: postgres:15
    environment: [POSTGRES_DB=spark, POSTGRES_PASSWORD=***]
    volumes: [pgdata:/var/lib/postgresql/data]
  cache:
    image: redis:7
  app:                      # Go 业务编排
    build: ./backend
    depends_on: [db, cache]
  compute:                  # Rust 计算内核
    build: ./compute
  web:
    image: nginx:alpine
    volumes: [./web/dist:/usr/share/nginx/html:ro]
```

### 1.3 环境变量

| 变量 | 说明 |
|---|---|
| `SPARK_DB_DSN` | 数据库连接串（生产强制，缺失拒启） |
| `SPARK_REDIS_URL` | 缓存 |
| `SPARK_SECRET_KEK` | 密钥加密主密钥（**不进 Git**） |
| `SPARK_LOG_LEVEL` | 日志级别 |

**纪律**：生产缺 DSN 直接拒启（fail-fast），不静默降级到本地 SQLite。

## 2. 配置与密钥

| 项 | 做法 |
|---|---|
| 密钥存储 | 只存引用（`*_ref`），实体在密钥库；DB 不落明文 |
| 加密 | KEK 主密钥 + 数据密钥（信封加密） |
| 轮换 | 90 天轮换；轮换期间新旧并行 |
| `.env` | 永不进 Git；CI 用 Secret 变量 |
| OAuth token | 加密落库，带 `expires_at`，自动刷新 |

## 3. 预计算运维

### 3.1 刷新任务

| 桶 | 频率 | 命令 | 预计耗时 |
|---|---|---|---|
| `pnl_daily` | 每日 T+1 | `spark-pc refresh pnl_daily` | < 30s |
| `pnl_month` | 每日 + 月终结转 | `spark-pc refresh pnl_month` | < 2min |
| `stock_snapshot` | 每日 | `spark-pc refresh stock_snapshot` | < 20s |
| `kpi_summary` | 每日 | `spark-pc refresh kpi_summary` | < 10s |

### 3.2 失效与重算

| 事件 | 动作 |
|---|---|
| 数据落地 | 标记相关桶 `stale` |
| 算法升版本 | `spark-pc rebucket --algo <id>` 只重算该算法产出的桶 |
| 规则变更 | `spark-pc rebucket --rule <id>` 重算依赖规则的桶 |
| 全量重建 | `spark-pc rebuild-all`（慎用，串行执行） |

### 3.3 健康检查

```bash
spark-pc status          # 各桶：行数 / 最后刷新 / algo_version / stale 标记
spark-pc verify          # 闸门：桶与源数据对平
```

## 4. 集成控制面运维

### 4.1 MCP / API 状态巡检

| 检查 | 频率 | 动作 |
|---|---|---|
| MCP 服务器探活 | 每小时 | 失败 → 状态置 `DEGRADED` + 告警 |
| API token 有效期 | 每日 | < 7 天 → 提醒刷新 |
| 配额消耗 | 每小时 | > 80% → 告警 |
| 账号启用状态 | 每次调用前 | `DISABLED` 直接拒绝 |

### 4.2 常见故障（承袭 KODP 实战经验）

| 症状 | 根因 | 处置 |
|---|---|---|
| 「已授权但发送失败」 | 授权状态 ≠ 可用性 | 查探活日志；确认机器人/账号在目标群/店 |
| 「BC 有但无 advertiser」 | 账号层级缺失 | 在平台侧补建 advertiser 账号 |
| 429 限流后长时间不恢复 | 无断点续传，整月重放 | 检查游标是否落库（§6.3） |
| Token 过期未自动刷新 | 刷新任务未跑 | 检查 OAuth refresh 任务 |
| 数值突然变化 | 口径/费率变更 | 查 `rule_version` 与策略历史 |

## 6. 备份、容灾与恢复（二轮修订 · 双云主备）

### 6.1 双云主备拓扑（D1 细化落地）

```
                 ┌───────────── 主（Primary）─────────────┐
                 │  阿里云 · 新加坡 (ap-southeast-1)       │
                 │  app(Go) + compute(Rust) + db(PG)       │
                 │  ← 全部读写流量                        │
                 └───────────────┬─────────────────────────┘
                                 │ 跨云异步同步（加密通道）
                                 │ WAL 流式 + 定期快照
                                 ▼
                 ┌───────────── 备（Standby）─────────────┐
                 │  AWS · 美国 (us-east-1)                 │
                 │  db(PG) 热备 + app/compute 冷备         │
                 │  ← 只读副本；主故障时提升             │
                 └───────────────────────────────────────┘
```

| 项 | 决策 |
|---|---|
| 主 | **阿里云 · 新加坡**（贴近泰国业务时区，承担全部读写） |
| 备 | **AWS · 美国**（us-east-1，热备只读副本 + 计算冷备） |
| 切换 | 主故障 → 提升备为主（手动/半自动，需 T1 确认）；DNS/VPN 切换 |
| 说明 | 双云避免厂商单点；RPO/RTO 见 §6.5 |

### 6.2 跨云异步同步

| 项 | 做法 |
|---|---|
| 方式 | **异步**（不阻塞主库写入，容忍秒级延迟） |
| 机制 | PostgreSQL **WAL 流式复制**（`pg_receivewal` / logical replication）+ 定期基线快照 |
| 通道 | 跨云**加密隧道**（WireGuard / 云专线），不直接暴露公网 |
| 延迟 | 正常 < 数秒；网络抖动时排队补偿，不丢数据 |
| 冲突 | 备为**只读**，单向主→备，无写冲突 |
| 监控 | 同步延迟指标；超阈值（如 > 60s）告警 |
| 切换后 | 原主恢复后降级为备，反向同步（需人工确认，避免脑裂） |

> **注意**：异步同步 ⇒ **RPO > 0**（可能丢最后几秒）。对经营数据（T+1 批处理）可接受；
> 若未来需 RPO=0 的强一致，需升级为同步复制（牺牲主库延迟），列入 F11。

### 6.3 备份云数据回滚（180 天）

| 项 | 决策 |
|---|---|
| 回滚窗口 | **备份云保留 180 天**可回滚点 |
| 回滚粒度 | 支持按**天**回滚（180 个回滚点）；月/周快照额外保留 |
| 触发方式 | 仅 **T1 管理员**可发起；需二次确认 + 记录理由 |
| 回滚对象 | 数据库（事实表 + 桶 + 配置）；不含审计表（审计**永不回滚**） |
| 隔离 | 回滚前先**快照当前状态**，便于反悔（回滚的回滚） |
| 演练 | 每季度演练一次，验证 180 天内任一点可恢复 |

```
可回滚点 = { 每日全量快照 × 180 天 } ∪ { 每周快照 × 52 周 }
回滚流程：选择回滚点 → 预览差异 → T1 二次确认 → 快照当前 → 执行回滚 → 校验 → 留痕
```

### 6.4 本地备份下载（月度配额）

用户要求：**云数据可本地备份，提供下载功能，但限制每月 1 次（1 号自动备份上一个月），有次数限制**。

| 项 | 决策 |
|---|---|
| 自动备份 | **每月 1 号**自动备份**上一个月**的数据，生成可下载归档 |
| 下载配额 | **每月 1 次**（自然月内仅可下载一次） |
| 配额重置 | 每月 1 日 00:00 重置 |
| 归档内容 | 上月数据导出（事实表 + 快照 + 必要维表），格式 CSV/Parquet + 校验和 |
| 加密 | 归档加密（受 KEK 保护），下载需 T1 授权 |
| 下载方式 | 一次性签名 URL（短时效，**不在 URL 中携带凭据**，符合 `docs/09`） |
| 次数限制 | 后端计数；超额直接拒绝并提示下次可下载时间 |
| 审计 | 每次下载记录：谁、何时、哪个月、文件校验和 |
| 手动补备 | 特殊情况下 T1 可手动触发一次"补备"，但不增加下月配额 |

```ts
// 备份下载配额模型
export interface BackupDownloadQuota {
  account: string;
  /** 自然月（YYYY-MM） */
  period: string;
  /** 本月已用次数 */
  used: number;
  /** 本月上限（默认 1） */
  limit: number;
  /** 下一次可下载时间 */
  nextAvailableAt: string;
  /** 可下载的归档列表（1 号自动生成的上月归档） */
  archives: {
    id: string;
    /** 数据月份，如 2026-09 */
    dataMonth: string;
    generatedAt: string;
    sizeBytes: number;
    sha256: string;
    /** 一次性签名 URL（短时效，不含凭据） */
    signedUrl?: string;
  }[];
}
```

> **纪律**：下载 URL 使用**一次性签名 + 短时效**，符合 `docs/09` 的「URL 不含账号密码」铁律；
> 归档文件**不得包含**任何密钥或明文凭据。

### 6.5 备份矩阵与 RPO/RTO

| 对象 | 频率 | 保留 | 方式 | RPO | RTO |
|---|---|---|---|---|---|
| PostgreSQL（主） | 每日全量 + WAL 归档 | 30 天 | `pg_dump` + WAL | < 1h | < 4h |
| PostgreSQL（备云） | 跨云异步同步 | **180 天回滚点** | WAL 流式 + 快照 | 秒级~分钟 | < 1h（提升备） |
| 原始层归档 | 每日 | 90 天 | JSONL + 对象存储 | 1 天 | < 4h |
| 配置/规则/算法 | 随 Git | 永久 | 版本控制 | — | 分钟 |
| 审计日志 | 实时 | ≥ 180 天 | append-only 表 | 0 | — |
| **本地备份下载** | **每月 1 号（上月）** | 归档永久（用户侧） | 加密归档 + 签名下载 | 1 月 | 小时 |

**恢复演练**：每季度一次，验证 RTO < 4h、RPO < 1h、180 天回滚点可达。

## 7. 采集链路运维（承袭 KODP 三层解耦）

```
采集层 ──► 原始层 ──► 投影层
（每页COMMIT）（只追加）（写业务表）
```

**护栏**

| 护栏 | 作用 |
|---|---|
| 请求节奏控制 | 控制单位时间调用数 |
| 429 乘性退避 | 降低撞限流概率 |
| 月度请求预算 | **注意**：触顶即放弃该月（KODP 的 fail-open 问题），本项目改为**告警 + 保留部分数据** |
| 分页重复硬失败 | 保证不重复计数 |
| 已覆盖月跳过 | 历史月不重放 |

**本项目改进**：预算触顶不再"放弃整月"，而是**落库已取得的部分 + 告警**，下轮续传。

## 8. 发布流程

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1. 构建 | `make build-all` | Go + Rust + 前端 |
| 2. 闸门 | `make gate` | 全部验收闸门（见 `04-验收闸门.md`） |
| 3. 打包 | `make pack` | 产物 + 版本号 |
| 4. 发布 | `deploy/install.sh` | 滚动更新 |
| 5. 验证 | `deploy/verify.sh` | 健康检查 + 冒烟 |

**回滚**：保留上一版镜像，`deploy/rollback.sh` 一键回退。
