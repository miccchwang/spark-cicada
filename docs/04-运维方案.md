## 1. 环境与部署

### 1.1 组件清单

| 组件 | 规格（参考） | 说明 |
|---|---|---|
| `app` | 2C4G | Go 服务（M-QUERY / M-SLOT / M-ADMIN / M-COLLECT） |
| `compute` | 4C8G | Rust 计算内核（预计算 / 算法执行） |
| `db` | 4C8G + SSD | PostgreSQL 15+ |
| `cache` | 2C4G | Redis |
| `web` | 静态 | Nginx / CDN |

> 最小可行（POC）：1 台 4C8G 跑全部，Compose 起。

### 1.2 部署形态

**默认 Docker Compose**（决策项 D9 建议；规模不需要 K8s）：

```yaml
# deploy/docker-compose.yml（骨架）
services:
  db:
    image: postgres:15
    environment: [POSTGRES_DB=spark, POSTGRES_PASSWORD=***]
    volumes: [pgdata:/var/lib/postgresql/data]
  cache:
    image: redis:7
  app:
    build: ./backend
    depends_on: [db, cache]
  compute:
    build: ./compute
  web:
    image: nginx:alpine
    volumes: [./web/dist:/usr/share/nginx/html:ro]
```

### 1.3 环境变量

| 变量 | 说明 |
|---|---|
| `SPARK_DB_DSN` | 数据库连接串（生产强制，缺失拒启） |
| `SPARK_REDIS_URL` | 缓存 |
| `SPARK_SECRET_KEK` | 密钥加密主密钥（**不进 Git**） |
| `SPARK_LOG_LEVEL` | 日志级别 |

**纪律**：生产缺 DSN 直接拒启（fail-fast），不静默降级到本地 SQLite。

## 2. 配置与密钥

| 项 | 做法 |
|---|---|
| 密钥存储 | 只存引用（`*_ref`），实体在密钥库；DB 不落明文 |
| 加密 | KEK 主密钥 + 数据密钥（信封加密） |
| 轮换 | 90 天轮换；轮换期间新旧并行 |
| `.env` | 永不进 Git；CI 用 Secret 变量 |
| OAuth token | 加密落库，带 `expires_at`，自动刷新 |

## 3. 预计算运维

### 3.1 刷新任务

| 桶 | 频率 | 命令 | 预计耗时 |
|---|---|---|---|
| `pnl_daily` | 每日 T+1 | `spark-pc refresh pnl_daily` | < 30s |
| `pnl_month` | 每日 + 月终结转 | `spark-pc refresh pnl_month` | < 2min |
| `stock_snapshot` | 每日 | `spark-pc refresh stock_snapshot` | < 20s |
| `kpi_summary` | 每日 | `spark-pc refresh kpi_summary` | < 10s |

### 3.2 失效与重算

| 事件 | 动作 |
|---|---|
| 数据落地 | 标记相关桶 `stale` |
| 算法升版本 | `spark-pc rebucket --algo <id>` 只重算该算法产出的桶 |
| 规则变更 | `spark-pc rebucket --rule <id>` 重算依赖规则的桶 |
| 全量重建 | `spark-pc rebuild-all`（慎用，串行执行） |

### 3.3 健康检查

```bash
spark-pc status          # 各桶：行数 / 最后刷新 / algo_version / stale 标记
spark-pc verify          # 闸门：桶与源数据对平
```

## 4. 集成控制面运维

### 4.1 MCP / API 状态巡检

| 检查 | 频率 | 动作 |
|---|---|---|
| MCP 服务器探活 | 每小时 | 失败 → 状态置 `DEGRADED` + 告警 |
| API token 有效期 | 每日 | < 7 天 → 提醒刷新 |
| 配额消耗 | 每小时 | > 80% → 告警 |
| 账号启用状态 | 每次调用前 | `DISABLED` 直接拒绝 |

### 4.2 常见故障（承袭 KODP 实战经验）

| 症状 | 根因 | 处置 |
|---|---|---|
| 「已授权但发送失败」 | 授权状态 ≠ 可用性 | 查探活日志；确认机器人/账号在目标群/店 |
| 「BC 有但无 advertiser」 | 账号层级缺失 | 在平台侧补建 advertiser 账号 |
| 429 限流后长时间不恢复 | 无断点续传，整月重放 | 检查游标是否落库（§6.3） |
| Token 过期未自动刷新 | 刷新任务未跑 | 检查 OAuth refresh 任务 |
| 数值突然变化 | 口径/费率变更 | 查 `rule_version` 与策略历史 |

## 5. 监控与告警

### 5.1 指标

| 类别 | 指标 |
|---|---|
| 性能 | TTI / 筛选 P95 / 查询 P95 / 缓存命中率 |
| 数据 | 各桶新鲜度 / 覆盖率 / 缺口数 |
| 集成 | 探活成功率 / 配额消耗 / 失败率 |
| 业务 | KPI 异常波动（超阈值报警） |

### 5.2 告警通道

- 即时：钉钉（本人账号 / 群，承袭 KODP 的 dws CLI 用法）
- 汇总：日报 / 周报
- 分级：`INFO` / `WARN` / `CRITICAL`

> **钉钉发送注意**：KODP 踩过「机器人不在目标群」的坑。
> 发送前须确认目标群已添加对应机器人，或用**本人账号**发送。

## 6. 备份与恢复

| 对象 | 频率 | 保留 | 方式 |
|---|---|---|---|
| PostgreSQL | 每日全量 + WAL 归档 | 30 天 | `pg_dump` + 异地同步 |
| 原始层归档 | 每日 | 90 天 | JSONL + 对象存储 |
| 配置/规则/算法 | 随 Git | 永久 | 版本控制 |
| 审计日志 | 实时 | ≥ 180 天 | append-only 表 |

**恢复演练**：每季度一次，验证 RTO < 4h、RPO < 1h。

## 7. 采集链路运维（承袭 KODP 三层解耦）

```
采集层 ──► 原始层 ──► 投影层
（每页COMMIT）（只追加）（写业务表）
```

**护栏**

| 护栏 | 作用 |
|---|---|
| 请求节奏控制 | 控制单位时间调用数 |
| 429 乘性退避 | 降低撞限流概率 |
| 月度请求预算 | **注意**：触顶即放弃该月（KODP 的 fail-open 问题），本项目改为**告警 + 保留部分数据** |
| 分页重复硬失败 | 保证不重复计数 |
| 已覆盖月跳过 | 历史月不重放 |

**本项目改进**：预算触顶不再"放弃整月"，而是**落库已取得的部分 + 告警**，下轮续传。

## 8. 发布流程

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1. 构建 | `make build-all` | Go + Rust + 前端 |
| 2. 闸门 | `make gate` | 全部验收闸门（见 `04-验收闸门.md`） |
| 3. 打包 | `make pack` | 产物 + 版本号 |
| 4. 发布 | `deploy/install.sh` | 滚动更新 |
| 5. 验证 | `deploy/verify.sh` | 健康检查 + 冒烟 |

**回滚**：保留上一版镜像，`deploy/rollback.sh` 一键回退。

## 9. 变更纪律

| 变更类型 | 必须同步 |
|---|---|
| 改算法 | `algorithms/*.yaml` + 升 version + 重算桶 |
| 改数据槽 | `slots/*.yaml` + 覆盖率复检 |
| 改规则 | `rules/*.yaml` + 升 version + 重算桶 |
| 改契约 | `contracts/` + 升版本号 + 迁移说明 |
| 改架构 | `docs/01` 同步更新 |
| 改口径 | `docs/03` §4.3 + 决策清单 |
